# NeuroConnect AI v2

A research prototype that takes **one whole-brain MRI volume** (`.nii` / `.nii.gz`)
and returns **one patient-level prediction**: `AUTISM` or `HEALTHY`.

The user never selects individual slices. The application loads the 3D volume,
finds the slices that actually contain brain tissue, scores each with an
EfficientNetB3 network, and combines those scores into a single result.

> ### ⚠️ This is a research prototype
> It is **not** a clinically validated diagnostic system, it has not been
> approved by any regulatory body, and it must **not** be used to make medical
> decisions about any real person. Autism is diagnosed by clinicians through
> behavioural assessment. No brain scan can diagnose it, and this software does
> not claim otherwise.

## 1. Before you start: the data

**No MRI data is included in this repository, and you should not add any.**

This project is built on **ABIDE-II** (Autism Brain Imaging Data Exchange II).
That dataset is distributed under a Data Usage Agreement that requires you to
register and does **not** permit redistribution. Committing the MRI volumes or
the phenotypic CSVs to a public repository would breach those terms and would
also publish human subject data.

To obtain the data yourself:

1. Go to the ABIDE-II page on NITRC / the ABIDE project site
   (<http://fcon_1000.projects.nitrc.org/indi/abide/abide_II.html>).
2. Register and accept the Data Usage Agreement.
3. Download the site archives you want, plus their phenotypic `.csv` files.

The pipeline is site-agnostic — it works with any subset of ABIDE-II sites you
download, as long as each site folder has a matching phenotypic CSV.

Download the ABIDE-II site archives and their phenotypic CSVs (see
[section 1](#1-before-you-start-the-data)), then arrange them in the folder
**that contains this project folder**:

```
<data folder>/
│
├── ABIDEII-BNI_1/              site folders: one directory per subject
│   ├── 29006/
│   │   └── session_1/
│   │       └── anat_1/
│   │           └── anat.nii.gz
│   ├── 29007/
│   └── ...
├── ABIDEII-GU_1/
├── ABIDEII-SDSU_1/
├── ABIDEII-STANFORD/
├── ABIDEII-TCD_1/
│
├── ABIDEII-BNI_1.csv           phenotypic file per site
├── ABIDEII-GU_1.csv
├── ABIDEII-SDSU_1.csv
├── ABIDEII-SU_2.csv
├── ABIDEII-TCD_1.csv
│
└── <this repo>/                create_dataset.py, train_model.py, app.py, ...
```

### Notes that save time

- **Subject folder names must be the numeric `SUB_ID`** used in the CSV. That
  is how patients are matched to their diagnosis.
- **Site folder names do not need to match the CSV names.** In the reference
  setup the folder is `ABIDEII-STANFORD` while its phenotypic file is
  `ABIDEII-SU_2.csv`. Matching is done on subject IDs, so this resolves
  automatically. You never need to edit a mapping table.
- **MRI filenames are not assumed.** Each subject folder is searched
  recursively for `*.nii` / `*.nii.gz`; anatomical scans are preferred and
  DTI / resting-state volumes are skipped.
- **CSV encodings vary.** UTF-8, Latin-1 and CP1252 are all handled
  automatically (`ABIDEII-GU_1.csv` is Latin-1, for example).

### If your data lives elsewhere

You do not have to move anything. Point the script at it:

```powershell
python create_dataset.py --raw-root "D:\ABIDE" --pheno-root "D:\ABIDE\pheno" --out-root "D:\output"
```

## 6. Running the pipeline

Run these in order, with the virtual environment activated. Each stage
validates itself before the next is useful.

### Step 1 — Build the dataset

```powershell
python create_dataset.py
```

Converts every subject's 3D MRI into 25 axial JPG slices and splits patients
into training and testing sets.

*Runtime: ~4 minutes for 306 subjects.*

Expected ending:

```
========================================
DATASET CREATION COMPLETE
========================================
Autism Training Patients  : 135
Healthy Training Patients : 131
Autism Testing Patients   : 20
Healthy Testing Patients  : 20
Training Images           : 6650
Testing Images            : 1000
Skipped Patients          : 0
Patient Leakage           : 0
========================================

VALIDATION PASSED - dataset is ready for training.
```

**`Patient Leakage` must be 0.** The script exits with an error otherwise.

### Step 2 — Train

```powershell
python train_model.py
```

Options:

```powershell
python train_model.py --stage1-epochs 16 --stage2-epochs 10 --batch-size 32
```

*Runtime: ~3 hours on a modern CPU (16 threads); far less on a CUDA GPU.*

Produces `Models/best_model.keras`, `Models/autism_detector.keras`,
`Models/model_config.json`, and the training curves in `Reports/`.

> **Do not run the app while training is in progress.** `best_model.keras` is
> rewritten every time validation AUC improves, so predictions will change
> between runs and mean nothing.

### Step 3 — Evaluate on the held-out patients

```powershell
python test_model.py
```

Scores the 20 Autism + 20 Healthy patients that were never used in training,
and writes `Reports/confusion_matrix.png`, `roc_curve.png` and
`classification_report.txt`.

*Runtime: ~2 minutes.*

### Step 4 (optional) — Collect whole MRIs for manual testing

```powershell
python export_test_mri.py
```

Copies the 40 held-out subjects' whole MRI volumes into a single flat folder
with self-describing names (`Autism_29006.nii.gz`, `Healthy_29020.nii.gz`), so
they are easy to pick in the GUI's file dialog.

## 7. Using the application

### GUI

Double-click **`run_app.bat`**, or:

```powershell
.\.venv\Scripts\python.exe app.py
```

Then: **Select Brain MRI** → choose a `.nii` / `.nii.gz` → **PREDICT**.

The window opens maximised. `F11` toggles true fullscreen, `Esc` exits it.

### Command line

```powershell
python test_model.py --mri "C:\path\to\patient_brain.nii.gz"
```

### Input validation

The application does not blindly accept arbitrary files. Every check below must
pass before any prediction is produced:

- extension is `.nii` or `.nii.gz`
- the file opens with `nibabel`
- the data is a 3D volume
- every dimension is between 32 and 1024 voxels
- the data is finite, non-empty and not constant
- at least 1% of voxels are non-background
- at least 10 brain-containing slices can be extracted

On failure it shows *"Invalid MRI file. Please select a valid whole-brain MRI
(.nii or .nii.gz)."* and produces **no** Autism/Healthy result.

## 8. Reading a prediction

```
AUTISM DETECTED                          HEALTHY
Autism Probability: 87.4%                Healthy Probability: 79.2%
Confidence: 88.0% (High)                 Confidence: 92.0% (High)
```

### The probability

The model's estimated score for that class. The two scores are complementary
and sum to 100%.

**It is not a measure of how much autism a person biologically has.** A score of
87% does not mean "87% autistic", and it does not mean the result is 87%
medically certain.

Because the decision threshold is chosen on the validation patients rather than
fixed at 50%, a `HEALTHY` verdict can occasionally carry a Healthy score
slightly below 50%. That is the model's genuine score, shown unaltered rather
than rescaled to look tidier, and such a case is always flagged Low confidence.

### The confidence

**Slice agreement** — the share of that MRI's brain slices whose own scores fell
on the same side of the decision threshold as the final answer.

This is deliberately not a restatement of the probability. It answers a
different question: *how consistent was the evidence?* Two patients can both
score 60% autism — one because every slice said 60%, another because half the
slices said 95% and half said 25%. Only the agreement figure distinguishes them.

The **High / Moderate / Low** label takes the weaker of two signals:

| Signal | Question | High | Moderate |
|---|---|---|---|
| Slice agreement | were the slices consistent? | ≥ 85% | ≥ 70% |
| Margin from threshold | did the score clear the line decisively? | ≥ 0.25 | ≥ 0.10 |

So `Confidence: 84.0% (Low)` is legitimate: the slices agreed, but the score
only just cleared the decision line. A verdict is only as strong as its weaker
signal.

**Confidence measures the model's internal agreement, not medical certainty.**
90% confidence does not mean 90% likely to be clinically correct — a
confidently wrong model is entirely possible. For that question, use the
measured held-out accuracy in `Reports/classification_report.txt`.

## 9. Troubleshooting

### `ModuleNotFoundError: No module named 'cv2'` (or `tensorflow`, `nibabel`)

**By far the most common problem.** You launched the script with the system
Python instead of the project's virtual environment. Dependencies were
installed into `.venv`, not system-wide.

```powershell
# Wrong -- uses system Python
python app.py

# Right
.\.venv\Scripts\python.exe app.py

# Or activate first, then plain python works
.\.venv\Scripts\Activate.ps1
python app.py
```

Double-clicking `app.py` in Explorer has the same problem. Use `run_app.bat`.

### `ERROR: No matching distribution found for tensorflow==2.19.0`

You are on Python 3.12+ or 3.13. TensorFlow 2.19 does not publish wheels for
them. Install Python 3.11 and recreate the virtual environment:

```powershell
Remove-Item -Recurse -Force .venv
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### `ERROR: no ABIDEII-* dataset folders found`

The data is not where the script expects. Either arrange it as shown in
[section 5](#5-getting-and-arranging-the-dataset), or pass explicit paths:

```powershell
python create_dataset.py --raw-root "D:\ABIDE" --out-root "D:\output"
```

### `ERROR: missing ...\MAIN_Training1\A1. Run create_dataset.py first.`

Run the stages in order: `create_dataset.py` → `train_model.py` → `test_model.py`.

### `No trained model at ...\best_model.keras. Run train_model.py first.`

The models are not tracked in git, so a fresh clone has none. Train first.

### The GUI's PREDICT button stays greyed out

The model has not finished loading, or it failed to load. Read the message in
the result panel — it names the exact cause and the command to fix it.

### Predictions change between runs on the same file

Training is still running and is rewriting `best_model.keras` underneath the
app. Wait for training to finish, or pass a fixed model:

```powershell
python test_model.py --mri scan.nii.gz --model Models\autism_detector.keras
```

### Windows blocks `Activate.ps1`

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### Training is extremely slow

It is CPU-bound by design if you have no CUDA GPU. To shorten a run:

```powershell
python train_model.py --stage1-epochs 8 --stage2-epochs 4
```

Accuracy will be lower. You can also reduce `SLICES_PER_PATIENT` in
`neuro_utils.py` (default 25) and rebuild the dataset for a smaller run.

## 10. How it works

### Dataset construction (`create_dataset.py`)

**Phenotypic matching.** Every `ABIDEII-*.csv` is read with automatic encoding
fallback (`utf-8-sig` → `utf-8` → `latin-1` → `cp1252`). `SUB_ID` identifies the
patient, `DX_GROUP` gives the label: **1 = Autism, 2 = Healthy**. No patient ID
is ever hard-coded.

**Slice extraction.** For each patient:

1. Load with `nibabel` and reorient to canonical **RAS**, so "axial" means the
   same thing for every site — the sites store their axes in different orders.
2. Normalise intensities using the 1st/99th percentile of foreground voxels;
   MRI intensity is not calibrated between scanners.
3. Build a tissue mask and keep only slices where ≥5% of pixels are tissue,
   discarding the empty air slices above and below the head.
4. Keep the central 80% of the brain's vertical extent and sample **25 slices
   evenly** across it. Slices are never chosen at random.
5. Crop to the brain bounding box, pad to square so the resize does not distort
   anatomy, and resize to **224 × 224**.

**Patient-wise split.** 20 Autism + 20 Healthy patients are held out, drawn
round-robin across sites so the held-out set is 4 Autism + 4 Healthy from every
scanner. This matters: if one site dominated the test set, a model that merely
recognised the scanner could look accurate. Every slice of a patient goes to
exactly one side, and the script re-reads what it wrote and fails if any
patient ID appears in both.

### Model and training (`train_model.py`)

**EfficientNetB3**, ImageNet pretrained, `include_top=False`, then global
average pooling, dropout 0.4, and a single sigmoid unit. Grayscale slices are
tiled to 3 channels; inputs stay on the 0–255 scale because EfficientNet
applies its own normalisation internally.

**Validation is also patient-wise** — the training patients are split 80/20 *by
patient*, class-stratified. Slice-level splitting would leak.

**Two-stage transfer learning:**

| Stage | What trains | Learning rate |
|---|---|---|
| 1 | Classification head only, backbone frozen | 1e-3 |
| 2 | `block6a` upward unfrozen, BatchNorm kept frozen | 1e-5 |

BatchNorm stays frozen during fine-tuning — re-estimating its statistics on a
few hundred patients is a common cause of fine-tuning collapse. The whole
backbone is deliberately not unfrozen: it is ~11× slower per step on CPU and
overfits badly at this dataset size.

Augmentation is mild and anatomy-preserving: horizontal flip (the brain is
roughly symmetric about the midline), ±4% rotation, ±8% zoom, ±5% translation,
contrast jitter. Callbacks: `ModelCheckpoint` on validation AUC,
`EarlyStopping`, `ReduceLROnPlateau`. Class weights offset the mild imbalance.
Decoded slices are cached in RAM so the JPGs are read once per run, not once
per epoch.

**Patient-level aggregation.** A patient has many slices but needs one answer.
Five rules — mean, median, trimmed mean, top-third mean, mean-of-logits — are
compared **on the validation patients**, never on the held-out test set. The
winner and the decision threshold (Youden's J on validation) are stored in
`Models/model_config.json` and reused identically by `test_model.py` and
`app.py`, so the GUI and the CLI can never disagree.

### Reproducibility

Seed 42 is applied to `random`, `numpy` and TensorFlow/Keras. Slice selection is
deterministic. The patient split is seeded and recorded in
`dataset_manifest.json` and `train_val_split.json`, so a rerun reproduces the
same assignment.

## 11. Results

### Measured result

| Metric | Validation (53 patients) | **Held-out test (40 patients)** |
|---|---|---|
| Accuracy | 71.7% | **52.5%** |
| AUC | 0.719 | **0.598** |
| Precision | — | 0.529 |
| Recall | — | 0.450 |
| F1 | — | 0.487 |

**The 85% target was not met, and this is not a near miss.** An AUC of 0.598
against 0.5 for random guessing means the model found only a very weak signal.
Mean patient score was 0.650 for autism and 0.614 for healthy — a separation of
0.036, with the two groups thoroughly interleaved.

These numbers are what the code produced. Nothing was adjusted, and no
threshold was tuned against the test set.

One disclosure about method: the test set was evaluated twice. The first run
used `top_k_mean` aggregation and scored 45.0%. That rule was then dropped —
because its threshold is not on the individual-slice scale, which made the
reported confidence incoherent, and because it had beaten plain `mean` by only
0.014 AUC on 53 validation patients, well inside noise. Both reasons come from
validation and design, not from the test outcome. But the 52.5% figure is a
second look at the same held-out set and is very slightly optimistic for that
reason.

Reproduce with `python test_model.py`. Outputs:

```
Reports/classification_report.txt    accuracy, precision, recall, F1, AUC
Reports/confusion_matrix.png
Reports/roc_curve.png
Reports/test_results.json            per-patient scores
```

**Set your expectations honestly.** Structural MRI is a weak signal for autism
classification. Published patient-level results on ABIDE with structural MRI
generally land in the 60–75% range, and this prototype is consistent with that
literature rather than an exception to it. If you see a number far above that,
suspect data leakage before celebrating.

The figures produced by this pipeline are the real measured outputs. Nothing is
hard-coded or adjusted.

## 12. Limitations

- **Structural MRI is a weak signal for autism.** This is a limitation of the
  problem, not of the implementation.
- **306 patients is a small dataset** for a 10.8M-parameter network.
- **Site variability.** The ABIDE-II sites use different scanners and
  protocols. Site-balancing the test set controls for this in the reported
  score, but does not remove scanner variability from the training data.
- **2D, not 3D.** The model sees axial slices independently and does not model
  3D structure directly.
- **Small per-site subsets.** Each site contributes 8 held-out patients, so
  per-site accuracy figures carry very wide error bars.
- **Not clinically validated.** Autism is diagnosed behaviourally by
  clinicians. This tool cannot and does not replace that.
